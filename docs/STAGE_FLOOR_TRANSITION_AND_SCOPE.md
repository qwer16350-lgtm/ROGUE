# Stage floor transition & state scope (SSOT)

**단일 근거 문서.** 층 전환 동작 방식과 “이 상태가 층에 묶이는지 / 런 전체에 묶이는지”를 새 기능 추가 시 반드시 판별할 때 참고한다. 구현 디테일(함수 이름·파일 목록)은 코드가 우선이다.

---

## 1. V1: 다음 층으로의 이동

- **플로우 요약:** 결과(또는 동등한 진입점)에서 “다음 층”이 승인되면, 현재 세계에서는 **`Teleport.toFloor`** 를 사용해 플레이어를 **같은 Stage Place의 새 reserved(전용 예약) 서버**로 재진입시키는 방식이다.
- **의미:** “한 층을 끝내고 같은 게임 플레이스로 다시 들어오되, 새 인스턴스가 구동되는” 패턴이다. 별칭적으로 **NextFloor = reserved 재진입** 으로 이해하면 된다.
- **`StageFlow`(및 근처 모듈)의 책임:** 다음 층(또는 스테이지 진행) **요청을 허용할지 말지**만 판단한다. 허용이면 현재 설계에서는 위 텔레포트 경로가 실제 이동을 담당한다.

---

## 2. 교체 가능한 경계(향후, 비목표)

- **현재 목표 외:** **같은 서버 인스턴스 안에서** 맵만 갈아끼우고 층 번호만 올리는 **same-server floor transition** 은 만들지 않는다고 가정한다.
- **설계 원칙:** 그럼에도 **`StageTransitionService`** 또는 **`FloorTransitionService`** 같은 이름으로 “실제 이동·월드 교체·세션 초기 범위”를 한곳으로 모으는 교체 가능성만 열어둔다.
  - `StageFlow`(또는 동등 레이어)는 계속 **정책(허용/거부·조건 검사)** 만 담당하고,
  - **어디로 어떻게 옮길지**는 전환 서비스로 분리할 수 있는 경계를 유지한다.

이 문서는 위 분리 가능성만 적어 두며, 해당 서비스의 구현·스케줄은 별 요청이다.

---

## 3. floor-scoped vs run-scoped

| 개념 | 의미 |
|------|------|
| **floor-scoped** | **현재 층(현재 세션 플레이 공간 한 단위)** 에만 속한다. 새 reserved 서버에 들어오면 **다시 깨끗하게 두어도 되는** 상태·엔티티·UI 신호. 같은 런이라도 층이 바뀌면 새 인스턴스 기준으로 **초기화·재생성**이 자연스럽다. |
| **run-scoped** | **이번 런 전체**(플레이어가 한 판을 깰 때까지)에 걸쳐 유지되어야 하는 상태. 층이 바뀌어도 **끌고 가야 하는** 것. 재진입 텔포트 후에도 **복원·복제·동일 값 유지**가 요구된다. |

모호하면: “예약 서버를 새로 받았을 때 디스크에 없던 것처럼 다시 깔려도 플레이어 체감이 맞는가?” → **floor** 쪽이다. 반대로 “플레이어 빌드·통화·메타 진행처럼 이 판이 끝날 때까지 기억해야 하는가?” → **run** 쪽이다.

### 3.1 floor-scoped 예시

- 적(enemies)·맵 타일(map tiles)·줍기(pickups)
- 피격 수치 표시 등 **표시 단위**(예: 데미지 넘버)
- **보스 체력 바**(해당 바가 “이 바닥 보스 한 마리” 전용이라면 floor)
- 해당 층 VFX·**웨이브 타이머**·**보스 스폰 여부/상태**(이 층에서만 의미 있는 것)

### 3.2 run-scoped 예시

- 플레이어 레벨·선택 업그레이드
- **`runId`** 같은 런 식별자, **현재 층 번호**(플레이어 관점 진행 표기)
- 파티 멤버 구성(이번 런에 함께 도는 사람)
- **누적 보상**(이번 판 종료까지 합산·보존해야 하는 것)

어떤 항목이 floor인지 run인지는 기능마다 다를 수 있다(예: “보스 바”가 글로벌 메타 HUD면 run에 가까울 수 있음). **항목 이름이 아니라 수명 규칙으로 판단**한다.

---

## 4. 신규 기능·상태 추가 시 규칙

**반드시** 다음을 명시한다.

1. 추가하는 서버 상태·복제 값·HUD·리모트 페이로드가 **floor-scoped 인지 run-scoped 인지** 한 줄로 결정한다.
2. 층 전환이 예약 재진입(V1)인지, 같은 서버 내 전환인지에 따라 초기화/유지 방법이 다를 수 있다. **V1에서는 재진입 시 floor-scoped 는 기본적으로 “새 인스턴스 = 새 바닥”** 전제와 맞는지 검토한다.
3. 상세 규칙 변경이 필요하면 본 문서를 갱신한다(직접 이 문서 수정 또는 “문서 패치 요청”).
